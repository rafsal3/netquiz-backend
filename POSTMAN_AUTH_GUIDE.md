# API Authentication Guide for Postman

This guide explains how to use the authentication token to test protected endpoints in Postman.

## How it Works
The backend uses **Firebase Auth** for security. To access protected routes (like `/admin/*` or `/progress/*`), you must include a valid **Firebase ID Token** in your request headers.

### Step 1: Obtain a Firebase ID Token
Since the backend relies on Firebase to verify users, you need a token generated by Firebase.

1.  **From the Web App (Easiest)**:
    - Log in to your application in the browser.
    - Open Developer Tools (F12 or Right Click > Inspect).
    - Go to the **Console** tab.
    - Run the following command if you have access to the Firebase `auth` object:
      ```javascript
      // Replace 'auth' with whatever your Firebase Auth instance is called
      (await auth.currentUser.getIdToken())
      ```
    - Copy the long string that appears.

2.  **Using Firebase REST API**:
    - You can also get a token by making a `POST` request to:  
      `https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=[YOUR_FIREBASE_API_KEY]`
    - Include `email`, `password`, and `returnSecureToken: true` in the JSON body.

---

### Step 2: Configure Postman
There are two ways to add the token in Postman:

#### Method A: Authorization Tab (Recommended)
1.  Open your request in Postman.
2.  Click on the **Authorization** tab.
3.  From the **Type** dropdown, select **Bearer Token**.
4.  Paste your copied ID Token into the **Token** field.
5.  Postman will automatically add the `Authorization: Bearer <your_token>` header for you.

#### Method B: Headers Tab
1.  Click on the **Headers** tab.
2.  Add a new key: `Authorization`.
3.  For the value, type `Bearer ` (with a space) followed by your token.  
    Example: `Bearer eyJhbGciOiJSUzI1NiIsImtpZCI6IjRi...`

---

### Step 3: Automating Token Management (Optional but Helpful)
Instead of pasting the token into every request, you can use a **Variable**.

1.  In Postman, create a new **Environment** (or use "Globals").
2.  Add a variable named `firebase_token`.
3.  Paste your token into the **Initial Value** and **Current Value**.
4.  In your request's Authorization tab (Method A), set the Token field to `{{firebase_token}}`.
5.  Now, when the token expires, you only need to update it once in the environment settings!

### Step 4: Core API Usage & Examples
These are the primary endpoints for managing the curriculum and community contributions.

#### 1. Curriculum (Papers, Modules, Submodules)
-   **Papers**:
    -   `GET {{baseUrl}}/curriculum/papers`: List all.
    -   `POST {{baseUrl}}/curriculum/papers`: Create.
    -   `PUT {{baseUrl}}/curriculum/papers/:id`: Edit (e.g., change name).
    -   `DELETE {{baseUrl}}/curriculum/papers/:id`: Delete.
-   **Modules**:
    -   `GET {{baseUrl}}/curriculum/modules?paperId=...`: List for a paper.
    -   `POST {{baseUrl}}/curriculum/modules`: Create (requires `paperId`).
    -   `PUT {{baseUrl}}/curriculum/modules/:id`: Edit.
    -   `DELETE {{baseUrl}}/curriculum/modules/:id`: Delete.
-   **Submodules**:
    -   `GET {{baseUrl}}/curriculum/submodules?moduleId=...`: List for a module.
    -   `POST {{baseUrl}}/curriculum/submodules`: Create (requires `moduleId`, `paperId`).
    -   `PUT {{baseUrl}}/curriculum/submodules/:id`: Edit.
    -   `DELETE {{baseUrl}}/curriculum/submodules/:id`: Delete.

#### 2. Questions
-   **GET {{baseUrl}}/questions**: Retrieve all (filtered).
-   **POST {{baseUrl}}/questions**: Create (Admin only).
-   **PUT {{baseUrl}}/questions/:id**: Update an existing question.
    -   **Body**: Any field you wish to update (e.g., `text`, `options`, `correct`).
-   **DELETE {{baseUrl}}/questions/:id**: Permanently removes a question.

#### 3. Community Submissions
-   **POST {{baseUrl}}/submissions**: User submission.
-   **GET {{baseUrl}}/submissions**: List (Admin can filter by `status`).
-   **PUT {{baseUrl}}/submissions/:id**: Edit a submission before approving it.
-   **PUT {{baseUrl}}/submissions/:id/approve**: Approve (creates a question).
-   **PUT {{baseUrl}}/submissions/:id/reject**: Reject.
-   **DELETE {{baseUrl}}/submissions/:id**: Delete a submission.

---

### Step 5: Admin API Usage & Examples
Admin routes are protected by both the `verifyToken` and `isAdmin` middleware. This means the token you use **must belong to a user listed in the `ADMIN_UIDS`** (defined in your `.env` file).

#### 1. List All Users
- **Endpoint**: `GET {{baseUrl}}/admin/users`
- **Query Params** (Optional): `search`, `page`, `limit`.
  
#### 2. Get Platform Stats
- **Endpoint**: `GET {{baseUrl}}/admin/stats`
- **Description**: Returns overall platform metrics like total users and active users today.

#### 3. Update User Role/Details
- **Endpoint**: `PUT {{baseUrl}}/admin/users/:uid`
- **Body**: `{ "role": "admin", "displayName": "Name" }`

---

### Pro-Tip: Setting a Base URL
In Postman, set a Global or Environment variable named `baseUrl`.
- **Value**: `http://localhost:5001` (or your production URL)
- **Usage**: Use `{{baseUrl}}/admin/users` in the URL bar.

---

### Common Issues
- **"Invalid token" (401)**: The token has expired (Firebase ID tokens last 1 hour).
- **"No token" (401)**: You forgot to add the `Authorization` header.
- **"Forbidden: Admin access required" (403)**: Your token is valid, but your `uid` is not present in the `ADMIN_UIDS` list.

---

> [!TIP]
> To test Admin features locally, make sure your own Firebase UID is added to the `ADMIN_UIDS` variable in your `.env` file!
